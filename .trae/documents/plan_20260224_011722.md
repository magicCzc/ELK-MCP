# 实现告警日志模糊搜索功能（最小化改动方案）

## 目标
在保持现有 API 向下兼容的前提下，增加通过关键字模糊搜索告警日志的功能。

## 实施步骤

### 1. 更新后端数据模型 (Python)
修改 `backend/app/models/schemas.py` 中的 `AlertsQueryRequest` 类，增加可选字段 `query`。
- **改动性质**：非破坏性更新（Optional Field）。
- **兼容性**：旧版本客户端请求不受影响。

### 2. 更新后端业务逻辑
修改 `backend/app/routes/logs.py` 中的 `alerts` 接口。
- **逻辑变更**：将请求中的 `query` 参数映射到 Elasticsearch 查询构建器的 `filters.keyword` 字段。
- **复用现有逻辑**：直接利用 `adapt_query_to_es6` 已有的模糊匹配功能，无需编写新的查询代码。

### 3. 更新前端类型定义 (TypeScript)
修改 `schemas-ts/src/schemas.ts`，同步更新 `AlertsQueryRequest` 的 Zod schema。
- **目的**：保持前后端类型一致，方便前端未来接入。

## 验证计划
1. 使用旧参数请求接口，确认功能正常（回归测试）。
2. 使用带 `query` 参数请求接口，确认能过滤出包含关键字的告警日志。
